# Dynamic vs preallocated CPU cache tradeoff v1: frozen protocol

2026-11-22 MYT, base `d015d2c4af6b3d858846178bf0a20ec950d21866`.
Two unchanged inference classes, same original untrained portable fixture with
canonical file and tensor SHA-256 checks, new standalone comparison only.
No training, checkpoint reconstruction, profiling, throughput, GPU or RSS.
Freeze this protocol, config, sources and reference receipts in a local commit
before the first timing. A local freeze is not public preregistration.

## Fixed workload and parity

CPU float32, deterministic algorithms, one intra-op and one inter-op thread,
BLAS environment thread controls set to one. For primary timing pin the process
to the lowest logical CPU in its initial eligible affinity, before importing
PyTorch, record the mask, runtime, clock and CPU model. Do not co-schedule this
primary workload with our other model calls, profiling or broad tests. Unknown
cloud neighbors, host contention, turbo/frequency, CPU siblings, and lack of
random independent machines remain limits. No dedicated-vCPU claim.

Run pre/post parity outside timing, same B2/P16/G16 and B2/P32/G32 portable-v1
prompt bytes, context 64, static batch capacity 2. At every greedy step compare
the two cache arms and full-prefix logits with combined atol=rtol=1e-5, exact
argmax IDs; additionally verify both real shared cached_request outputs and
full-prefix request are byte-identical. Run 1 prefill and G−1 appends; the last
generated byte is not forwarded. Verify model and tested snapshots keep the
original tensor identity. Statics are not a new default.

One common process-warm constructor-only cell (same model/capacity details for
both cases), then new and reused request cells per case, short before long.
New-session = constructor including weight validation/deepcopy and first
`cached_request`, returning both session and output. Reused-session = own
snapshot created before measurement, but every call includes `cached_request`
reset, prompt clone/validation, prefill, appends, greedy selection and output.
Batched in-process requests are sequential, not throughput. Reset overhead
for releasing prior dynamic active state is part of the reused-session API;
first reuse starts with an empty session for each arm before warmup.
Construction-only keeps the fresh snapshot alive through stop. Returned session
and output are deliberately dereferenced after the stop clock, outside every
sample. No setup/teardown subtraction or invented append-only result.

## Sampling and aggregation

Per cell 6 paired warmups, then 30 paired wall-clock samples, exactly one call
per arm per pair. Both series alternate AB/BA; even cell indexes start dynamic,
odd cell indexes start preallocated. Store every measured duration and order
with no filtering, denominator changes or winner-based reruns. Time a
`perf_counter_ns` boundary before/after one callable; record 256 empty callable
boundaries as a clock/harness-floor sanity check, not a subtraction. Garbage
collector state stays unchanged. No assertions, resource accounting, output
conversion, comparison, profiler or stdout in timed operations. The unprofiled
production paths still run their own validation and normal no-op scope calls.

Report min/median/nearest-rank p90/max in ns, per-arm and paired preallocated
/divided by dynamic ratio; median static−dynamic difference in ns and count
of pairs with each direction, all descriptive. Include first-arm stratified
median ratios to flag order effects, not an adjustment. Each percentile is a
single-call sample, not a batch mean and not a service tail statistic. No
statistical significance, confidence interval, generalized speedup or
comparison with older independently measured latency is appropriate.

Retain partial data and report first primary failure if it happens; do not
replace by cherry-picked reruns. Full run requires distinct output path and
takes no tuning flags. Reproducibility means workload and calculations, not
identical clocks across runs. `--check-only` runs real parity/resource checks
without timing or affinity change (CI). `--audit` recomputes saved arithmetic
and checks source identities, without rerunning inference/measurement.

## Retention outside timing

Use unique actual K/V forward storage identities, not lengths as a proxy for
backing nbytes. Snapshot, optimizer, token output, transient operators,
allocator/caching behavior and Python memory are excluded. Observe each arm
at empty construction, after complete request, and after reset. No untyped
storage or external tensor reference survives bookkeeping, so reset reports
session ownership, not physical release/erasure.

For CPU f32 two-layer width 64 B2, both active payloads predict 63,488/129,024 B
at lengths 31/63. Dynamic owned distinct K/V storage predicts 0 at idle/reset
and final backing equal to active; static predicts four 32,768 B storages
(131,072 B) across all three checkpoints. Static pointers stay stable; raw
addresses are not published. A fixed reserve can cost more on short/idle
sessions; this is not RSS, peak, allocation traffic or a memory-saving claim.

## Affinity enforcement correction before compliant measurement

The first raw execution is preserved verbatim as
`results/cache-tradeoff-v1/deviations/pre-affinity-import.json`, ineligible for
the primary comparison regardless of its values. A no-Torch audit exposed that
resolving a package resource had imported Torch indirectly before pinning.
Although all model work followed the main-thread pin, the prior import did not
satisfy this protocol. The corrected helper resolves installed source paths
without importing packages; the runner fails before pinning if Torch is already
loaded and checks every observable Linux native thread has exactly the chosen
affinity before parity and after timings. The same workload and sample plan
remain fixed. This correction is frozen locally before the first compliant run.
The field `empty_boundary_pairs` counts pairs of clock reads, not A/B arms.

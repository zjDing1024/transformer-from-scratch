# Standalone portable CPU parity and scoped memory check

2026-11-19 MYT. This closes a reproduction gap: the new checker runs without an
unpublished checkpoint, training, external data or network calls. It uses a
separately named **untrained fixed-weight fixture**, not the original language
model or the Nov 18 reconstructed candidate. Historical failures/results are untouched.

## Install and run outside the checkout

```bash
python -m pip install torch==2.14.1 --index-url https://download.pytorch.org/whl/cpu
python -m pip install .
transformer-cpu-check --parity-only --output parity.json
# Linux: also attempt own-process phase-memory observations + coarse positive controls.
transformer-cpu-check --output memory.json
```

The installed wheel includes its manifest. `python -m transformer_diagnostics.cli`
is equivalent. Each child has a 120-second timeout; existing output files are refused,
not overwritten. The parent is standard-library only and never imports Torch.
Parity is checked in a fresh process before four serial memory workers.
`--parity-only` neither resets memory counters nor performs the resident-memory control.

The default memory check writes only `5` to each worker's own `/proc/self/clear_refs`,
which resets its peak RSS accounting. It never changes another PID, data, memory
protections, global settings or security controls. Missing/denied Linux facilities
produce explicit unavailable memory status, not fictitious zeros or success.
Parity checks still run. No GPU or server is implemented; no latency measurement is made.

## A separately identified portable artifact

Fixture: `byte-lm-portable-f32-v1`, 99,968 parameters, same architecture as the earlier
small LM. Every tensor is filled from SHAKE256 integer codes and exactly representable
binary fractions. Constructor RNG is restored and random initial values are overwritten.
This is a byte-level fixture generation recipe, not a historical recovery/trained model.
No re-ranking, repeated 600-step training or model-quality evaluation occurred.

- Canonical artifact: 403,088 bytes, SHA256
  `72b3fcbbd1233973e8dadd98c7ab8f3d0d33c8b4b4f272d0e55c24cfb381e597`.
- Tensor digest:
  `9ab16b65155a55a2860c6f851f0d69a6ad072885b1342ac0fa4c754d9096813e`.
- The canonical container is an explicit header plus little-endian float32 bytes,
  NOT a pickle or torch-save zip. Its small identity/recipe manifest is packaged;
  full bytes regenerate locally. Both identity checks run before inference.
- To inspect/export those canonical bytes locally (not required for the checker):

```python
from transformer_core.portable_fixture import verified_fixture

model, artifact, identity = verified_fixture()
with open("portable-v1.plm", "xb") as target:
    target.write(artifact)
print(identity)
```

Fixture bytes matched between source-tree and installed-wheel processes. This is
not evidence of identical logits across arbitrary hardware/backends or native
Windows testing. Generated bytes are arbitrary, not meaningful language samples.

Teacher-forced cached logits vs the full 64-token oracle:

| Chunk schedule | Maximum absolute error |
| --- | ---: |
| `[64]` | 0 |
| 64 single tokens | 9.5367431640625e-7 |
| `[5,13,1,17,28]` | 8.344650268554688e-7 |

Fresh-prefix comparisons also passed their assertions; the table's maxima refer
specifically to the full 64-token comparison, not an unrecorded combined maximum.
Greedy last-position logits vs full-prefix maximum errors were 7.152557373046875e-7
(B2/P16/G16) and 1.0728836059570312e-6 (B2/P32/G32). All checks use combined
`atol=rtol=1e-5`, not bitwise logit equality. Both fixed trajectories' greedy byte IDs
matched exactly, with no forward of the final emitted byte. There is no universal
near-tie/output guarantee. Cache lengths 31 / 63 imply 62 / 126 KiB exact K/V payload.

### Phase-memory observations, not a memory-saving result

The same source model stays live in every worker; cached workers additionally own
the real snapshot. After construction/hashing/setup, mode 5 resets the phase peak.
The request runs once, with model/session/output still alive when readings are taken.
This includes process/library/allocator state, not exclusive model allocations.

All values below are KiB (one observation per arm/case). In this run setup and
post-reset VmRSS were equal, and post-request VmRSS equaled VmHWM:

| B / P / G | Arm | Setup VmRSS | Post-reset VmRSS | Request-window VmHWM | Exact K/V payload |
| --- | --- | ---: | ---: | ---: | ---: |
| 2 / 16 / 16 | full prefix | 283,392 | 283,392 | 291,140 | 0 |
| 2 / 16 / 16 | cached | 286,140 | 286,140 | 292,412 | 62 |
| 2 / 32 / 32 | full prefix | 283,396 | 283,396 | 291,544 | 0 |
| 2 / 32 / 32 | cached | 286,064 | 286,064 | 292,252 | 126 |

A separate positive-control window followed each request: touch every page of a
private anonymous 16 MiB mapping, read while live, release, read again. All four
controls increased both VmRSS and VmHWM by 16,388 KiB, exceeding the predeclared 12 MiB
coarse threshold. Post-release RSS returned to within 4 KiB of each control baseline.
**Control peaks are not substituted for the preceding request peaks.**

This demonstrates response to a large controlled resident-memory change here.
It does not establish precision at 62 / 126 KiB, justify attributing process differences
to tensors/snapshot bytes, or prove a cache-memory benefit. The cached absolute
request peaks were not lower in these single observations. Do not turn smaller
raw phase deltas into a savings claim, or subtract independent-process values as
if measuring an allocation. No repetition/distribution or general memory comparison
was attempted. New VmHWM observations do not diagnose the old flat ru_maxrss result.

Raw `ru_maxrss` remains separately recorded because it can include prior/exec high
water. Its values need not equal VmHWM; it is never used as the phase endpoint.
`raw_rss_change_kib` and `raw_hwm_minus_baseline_rss_kib` are merely numerical
snapshot differences, even when a phase is invalid; negative values are preserved.
Use `request_window_status` AND `positive_control.status` before interpreting a
window. `request_phase_peak_kib` is explicitly unavailable unless reset/metrics/
coarse control all pass. No proc support, failed reset, malformed/Unicode fields
or insufficient control response is silently replaced with zero or ru_maxrss.

## Tests, wheel and CI boundary

210 local CPU tests passed (191 historical + 19 new), Ruff/format/compileall passed.
New tests cover canonical payload/tensor identities, RNG isolation, fixed-fixture
parity, light-launcher imports, CLI refusal to overwrite, malformed/unavailable
metrics, negative deltas and control/reset failure. OS/unavailable branches are
mocked regressions, not a claimed native Windows run. Missing optional NumPy raises
one harmless warning and is unused.

A wheel was built offline without fetching dependencies, installed into a separate
location, and its command ran from outside the repository. Its fixture identities,
parity object and source-file hashes matched the source run exactly. The replay
used parity-only mode; no second memory run was performed to select nicer readings.

Existing CI now invokes the actual `python -m transformer_diagnostics.cli
--parity-only --output results/ci-portable.json` after tests/mechanism checks. That
executes fixture generation and cached/reference inference on the CI runtime; it
is not just an audit of published JSON. CI does NOT assert RSS values, run mode 5,
or require positive-control thresholds. Historical frozen benchmark records still
have their existing offline audit tests. Local checks are verified here; only the
publisher can confirm the final remote commit's CI outcome.
